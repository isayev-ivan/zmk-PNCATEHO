# Руководство по репозиторию ZMK-PNCATEHO

Этот репозиторий содержит конфигурацию прошивки ZMK для клавиатуры **PNCATEHO**. Ниже описана структура файлов и инструкция по работе с ними.

## Структура репозитория

```
zmk-PNCATEHO/
├── .github/workflows/   # Автоматизация сборки (GitHub Actions)
│   └── build.yml        # Сценарий сборки прошивки при пуше в репозиторий
├── config/              # Основная папка с вашей конфигурацией
│   ├── PNCATEHO.conf    # Глобальные настройки (Bluetooth, сон, питание)
│   ├── west.yml         # Манифест зависимостей (управляет версиями модулей ZMK)
│   └── boards/shields/PNCATEHO/  # Определение вашего "щита" (клавиатуры)
│       ├── PNCATEHO.keymap       # Основная карта клавиш
│       ├── PNCATEHO.dtsi         # Описание "железа" (матрица, пины)
│       ├── chords.dtsi           # Описание аккордов (Combos) - САМОЕ ВАЖНОЕ
│       ├── *.overlay             # Наложения для левой/правой половинок
│       └── Kconfig.*             # Настройки меню конфигурации
└── build.yaml           # Настройки для локальной сборки или CI
```

## Где что находится и как редактировать

### 1. Изменение раскладки (Keymap)
Ваша клавиатура использует **аккордовый ввод** (комбинации клавиш).

*   **Файл:** `config/boards/shields/PNCATEHO/chords.dtsi`
*   **Как это работает:** В этом файле определены макросы `TCOMBO`.
    *   Пример: `TCOMBO(B, &kp B, &kp LS(B), ...)`
    *   Это означает, что при нажатии определенной комбинации клавиш (определенной в аргументах `TLP`, `TRP` и т.д.) будет отправлен код `B`.
*   **Базовый слой:** Файл `config/boards/shields/PNCATEHO/PNCATEHO.keymap` в данный момент почти пуст (`&none`). Это нормально для чисто аккордовой клавиатуры, где все действия вызываются через `combos`.

### 2. Настройки системы (Сон, Bluetooth)
*   **Файл:** `config/PNCATEHO.conf`
*   Здесь можно включить/выключить подсветку, изменить время ухода в сон (`CONFIG_ZMK_IDLE_SLEEP_TIMEOUT`), настроить мощность Bluetooth.

### 3. Описание "Железа"
*   **Файлы:** `config/boards/shields/PNCATEHO/*.overlay` и `PNCATEHO.dtsi`
*   Редактируйте эти файлы только если вы физически изменили пайку, пины контроллера или матрицу клавиатуры.

## Как работать с прошивкой (Workflow)

ZMK использует подход "Cloud First" (Сборка в облаке), но возможна и локальная сборка.

### Вариант 1: Сборка через GitHub (Рекомендуемый)
1.  Отредактируйте файлы (например, измените аккорд в `chords.dtsi`).
2.  Сделайте `git commit` и `git push`.
3.  Зайдите на вкладку **Actions** в вашем репозитории на GitHub.
4.  Вы увидите запущенный процесс сборки.
5.  Когда он завершится (зеленая галочка), скачайте артефакт `firmware.zip`.
6.  Распакуйте архив и прошейте файлы `.uf2` в контроллеры клавиатуры (подключите по USB, нажмите Reset дважды, скопируйте файл на диск `NICENANO` или аналогичный).

### Вариант 2: Локальная сборка (Для продвинутых)
Вам потребуется установленный Docker или настроенное окружение Zephyr/West.
Команда для сборки (примерная):
```bash
west build -b nice_nano -- -DSHIELD=PNCATEHO_left
west build -b nice_nano -- -DSHIELD=PNCATEHO_right
```

## Советы по редактированию `chords.dtsi`
Файл использует макрос C-препроцессора `TCOMBO`.
Аргументы макроса (примерно):
1.  `NAME`: Имя комбо (для внутреннего использования).
2.  `BINDINGS`: Что происходит при обычном нажатии аккорда.
3.  `INNER_BINDINGS`: Что происходит при нажатии аккорда + внутренний большой палец.
4.  `OUTER_BINDINGS`: Что происходит при нажатии аккорда + внешний большой палец.
5.  `BOTH_BINDINGS`: Аккорд + оба больших пальца.
6.  `LEFT_KEYPOS` / `RIGHT_KEYPOS`: Позиции клавиш, которые нужно нажать для срабатывания аккорда.
