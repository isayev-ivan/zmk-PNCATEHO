# Разбор кода прошивки

В этом файле мы будем собирать подробные объяснения того, как устроены исходные файлы прошивки клавиатуры.

## /config/boards/shields/PNCATEHO/PNCATEHO.keymap

Этот файл — "скелет" раскладки. Он определяет базовые настройки, тайминги и связывает физические кнопки с логикой аккордов.

### 1. Подключение библиотек (строки 1-10)

```c
#include <behaviors.dtsi>
#include <dt-bindings/zmk/bt.h>
// ...
```

Здесь подключаются стандартные модули ZMK:
*   `behaviors.dtsi`: описывает поведение клавиш (нажатие, удержание, липкие клавиши).
*   `bt.h`, `keys.h`, `outputs.h`: коды клавиш (A, B, C...), управления Bluetooth и питанием.

### 2. Настройки таймингов (строки 12-15)

```c
#define COMBO_TIMEOUT 70
#define STICKY_TIMEOUT 500
```

*   `COMBO_TIMEOUT 70`: **Критически важная настройка**. Это время ожидания аккорда в миллисекундах. У тебя есть всего **70 мс**, чтобы нажать все клавиши аккорда. Если не успел — сработают отдельные нажатия (или ничего, если не настроено).
*   `STICKY_TIMEOUT 500`: Время жизни "липкой" клавиши (например, Shift). Если нажал Shift и ничего не нажал в течение 0.5 сек — он "отлипнет".

### 3. Карта физических клавиш (строки 17-39)

Здесь задаются понятные имена (alias) для физических номеров клавиш, чтобы не писать в коде цифры.

**Левая рука (Left Side):**
*   `TLP` (Top Left Pinky) = `0` — Мизинец, верхний ряд.
*   `TLR` (Top Left Ring) = `1` — Безымянный, верхний ряд.
*   `LOT` (Left Outer Thumb) = `16` — Левый **Внешний** большой палец.
*   `LIT` (Left Inner Thumb) = `17` — Левый **Внутренний** большой палец.

Аналогично для **Правой руки (Right Side)** (`TRP`, `TRR`...).

### 4. Настройка липких клавиш (строки 41-44)

```c
&sk {
    release-after-ms = <STICKY_TIMEOUT>;
    quick-release;
};
```

Настройка поведения Sticky Keys (`&sk`):
*   `quick-release`: Если ты нажал `Sticky Shift`, а затем букву — Shift применится и сразу "отлипнет". Без этой настройки он мог бы остаться нажатым для следующей буквы при очень быстрой печати.

### 5. Главная логика и пустой слой (строки 46-63)

```c
/ {
  combos {
    compatible = "zmk,combos";
    #include "chords.dtsi"
  };

  keymap {
    compatible = "zmk,keymap";

    default_layer {
      bindings = <
        &none &none &none &none ...
      >;
    };
  };
};
```

*   **`combos { #include "chords.dtsi" };`**:
    Подключает файл `chords.dtsi`, который содержит **все** определения букв и символов. Именно там сказано, какие комбинации клавиш какие символы дают.

*   **`default_layer` c `&none`**:
    Базовый слой полностью заполнен `&none`. Это значит, что **клавиатура работает только на аккордах**.

### Почему работают одиночные клавиши?

Хотя слой пустой, одиночные нажатия работают, потому что **для прошивки они тоже являются аккордами**.

В файле `chords.dtsi` используется макрос `TCOMBO`, который превращает каждую одиночную клавишу в "аккорд из одной кнопки".
Когда ты нажимаешь букву (например, `B`):
1. Прошивка видит нажатие физической кнопки.
2. Ждет 70 мс (`COMBO_TIMEOUT`), чтобы проверить, не нажмешь ли ты еще что-то (например, большой палец для модификации).
3. Если ничего больше не нажато — срабатывает "аккорд", выдающий букву `B`.

Это позволяет "навешивать" на любую одиночную клавишу дополнительные функции через большие пальцы (модификаторы), не меняя базовую логику.

## /config/boards/shields/PNCATEHO/PNCATEHO.dtsi

Этот файл описывает "железо" клавиатуры: как именно физические кнопки подключены к микроконтроллеру.

### 1. Выбор конфигурации (строки 9-13)

```c
chosen {
    zmk,kscan = &kscan0;
    zmk,matrix_transform = &default_transform;
};
```

Здесь мы говорим прошивке:
*   Для сканирования клавиш используй конфигурацию `kscan0`.
*   Для превращения физических контактов в логическую сетку используй `default_transform`.

### 2. Матричная трансформация (строки 15-24)

```c
default_transform: keymap_transform_0 {
    compatible = "zmk,matrix-transform";
    columns = <8>;
    rows = <3>;
    map = <
    RC(0,0) RC(0,1) ...
    >;
};
```

Это карта того, как физические кнопки (которые мы нажимаем) соответствуют логическим индексам в прошивке.
*   `columns = <8>` / `rows = <3>`: У клавиатуры логически 8 колонок и 3 ряда.
*   `RC(0,0)`: Означает Row 0, Column 0. Это первая кнопка (левый мизинец, верхний ряд).

Именно эти индексы (0, 1, 2...) используются потом в файле `PNCATEHO.keymap` под именами `TLP`, `TLR` и т.д.

### 3. Сканирование клавиш (строки 26-42)

```c
kscan0: kscan {
    compatible = "zmk,kscan-gpio-direct";
    input-gpios = <&pro_micro 18 ...>, ...;
};
```

*   `zmk,kscan-gpio-direct`: Это означает, что **у клавиатуры нет матрицы** (строк и столбцов в привычном понимании). Каждая кнопка подключена к своему отдельному пину микроконтроллера напрямую.
*   `input-gpios`: Список пинов на плате Pro Micro, куда припаяны кнопки.
    *   `GPIO_ACTIVE_LOW`: Кнопка срабатывает, когда замыкает контакт на землю (GND).
    *   `GPIO_PULL_UP`: Включить встроенный подтягивающий резистор, чтобы не было ложных срабатываний.

## /config/boards/shields/PNCATEHO/chords.dtsi

Этот файл — "мозги" раскладки. Здесь определены все комбинации клавиш (аккорды), которые превращаются в символы.

### 1. Макрос `TCOMBO` (строки 1-49)

Чтобы не писать вручную сотни строк кода для каждой клавиши, здесь используется мощный C-макрос `TCOMBO`. Он автоматически создает **4 варианта поведения** для каждого символа:

```c
#define TCOMBO(NAME, BINDINGS, INNER_BINDINGS, OUTER_BINDINGS, BOTH_BINDINGS, LEFT_KEYPOS, RIGHT_KEYPOS) \
    // ... (разворачивается в 8 определений комбо: 4 для левой руки, 4 для правой)
```

Для каждой буквы (например, `A`) макрос создает:
1.  **Обычное нажатие** (`combo_l_A` / `combo_r_A`):
    *   Срабатывает при нажатии основных клавиш (`KEYPOS`).
    *   Выдает символ из `BINDINGS` (например, `&kp A`).
2.  **С внутренним пальцем** (`combo_li_A` / `combo_ri_A`):
    *   Срабатывает при нажатии основных клавиш + `LIT` (Left Inner Thumb).
    *   Выдает символ из `INNER_BINDINGS` (например, `Shift + A` или спецсимвол).
3.  **С внешним пальцем** (`combo_lo_A` / `combo_ro_A`):
    *   Срабатывает при нажатии основных клавиш + `LOT` (Left Outer Thumb).
    *   Выдает символ из `OUTER_BINDINGS` (обычно цифры или символы).
4.  **С обоими пальцами** (`combo_lb_A` / `combo_rb_A`):
    *   Срабатывает при нажатии основных клавиш + `LIT` + `LOT`.
    *   Выдает символ из `BOTH_BINDINGS` (редко используется, обычно функциональные клавиши).

Таким образом, одна строка определения внизу файла генерирует сразу **8** комбинаций (4 для левой руки и 4 для правой, если позиция зеркальна).

### 2. Специальные комбо (строки 51-77)

Здесь вручную (без макроса) определены самые часто используемые клавиши, которые всегда должны быть под большими пальцами:
*   **Space (Пробел)**: Внутренний большой палец (`LIT` / `RIT`).
*   **Backspace (Удаление)**: Внешний большой палец (`LOT` / `ROT`).

Это значит, что если нажать *только* большой палец — сработает Пробел или Backspace. А если нажать его *вместе* с другими клавишами — он сработает как модификатор (см. пункт 1).

### 3. Таблица аккордов (строки 79-118)

Это самая важная часть, где задается раскладка. Разберем на примере буквы `B` (строка 79):

```c
//     (Имя,  Обычное,    Внутр.палец,   Внешн.палец,  Оба пальца,    Левый аккорд, Правый аккорд)
TCOMBO(B,     &kp B,      &kp LS(B),     &kp LEFT,     &kp LS(LEFT),  TLP,          TRP)
```

*   **`B`**: Внутреннее имя комбо.
*   **`&kp B`**: Что будет при обычном нажатии (`TLP` - мизинец верхний ряд). -> Печатается `b`.
*   **`&kp LS(B)`**: Что будет с **внутренним** большим пальцем. -> Печатается `B` (Shift+B).
*   **`&kp LEFT`**: Что будет с **внешним** большим пальцем. -> Нажимается стрелка влево.
*   **`&kp LS(LEFT)`**: Что будет с **двумя** большими пальцами. -> Выделение влево (Shift+Left).
*   **`TLP` / `TRP`**: Какие физические кнопки нужно нажать для этого аккорда (Левый мизинец / Правый мизинец).

#### Пример сложного аккорда (строка 105, Точка)

```c
TCOMBO(DOT, &kp DOT, &kp LS(DOT), &kp LPAR, &none, TLP BLR, TRP BRR)
```

*   **Клавиши**: `TLP BLR` (Левый мизинец верх + Левый безымянный низ).
*   **Результат**: `.` (точка).
*   **С внутр. пальцем**: `>` (Shift + точка).
*   **С внешн. пальцем**: `(` (левая скобка).

## /config/boards/shields/PNCATEHO/PNCATEHO.conf

Файл пользовательских настроек (Kconfig). Здесь включаются или выключаются глобальные функции прошивки.

```ini
CONFIG_ZMK_SLEEP=y
CONFIG_ZMK_IDLE_SLEEP_TIMEOUT=900000
CONFIG_ZMK_KEYBOARD_NAME="PNCATEHO"
```

*   `CONFIG_ZMK_SLEEP=y`: Включает режим глубокого сна (Deep Sleep) для экономии батареи.
*   `CONFIG_ZMK_IDLE_SLEEP_TIMEOUT=900000`: Время бездействия перед уходом в глубокий сон. 900 000 мс = **15 минут**.
*   `CONFIG_ZMK_KEYBOARD_NAME="PNCATEHO"`: Имя, которое будет отображаться при поиске Bluetooth-устройств.
*   `CONFIG_ZMK_RGB_UNDERGLOW=n`: Отключение подсветки (для экономии энергии).

## /config/boards/shields/PNCATEHO/Kconfig.shield

Этот файл регистрирует "щит" (нашу клавиатуру) в системе сборки ZMK.

```makefile
config SHIELD_PNCATEHO_LEFT
    def_bool $(shields_list_contains,PNCATEHO_left)

config SHIELD_PNCATEHO_RIGHT
    def_bool $(shields_list_contains,PNCATEHO_right)
```

Он сообщает системе, что существуют две половины клавиатуры: `PNCATEHO_left` и `PNCATEHO_right`. Если мы собираем прошивку для левой части, активируется первая опция.

## /config/boards/shields/PNCATEHO/Kconfig.defconfig

Файл значений по умолчанию, которые применяются, если выбран этот щит.

```makefile
if SHIELD_PNCATEHO_LEFT || SHIELD_PNCATEHO_RIGHT
config ZMK_SPLIT
    default y
endif
```

*   `config ZMK_SPLIT default y`: Самая важная строка. Она говорит прошивке: "Это **раздельная** (split) клавиатура". Прошивка автоматически включит логику общения между половинками.
*   `ZMK_SPLIT_ROLE_CENTRAL default y` (для левой): Говорит, что левая половинка — главная (Central). Она подключается к компьютеру по Bluetooth, а правая половинка (Peripheral) подключается к левой.

## /config/boards/shields/PNCATEHO/PNCATEHO_left.overlay и PNCATEHO_right.overlay

Файлы наложения (overlay), которые уточняют `PNCATEHO.dtsi` для конкретной половинки.

**PNCATEHO_left.overlay**:
Просто подключает общий файл `PNCATEHO.dtsi`.

**PNCATEHO_right.overlay**:
```c
&default_transform {
	col-offset = <10>;
};
```
*   `col-offset = <10>`: Это критически важно для правой половинки.
    В общем файле `PNCATEHO.dtsi` матрица имеет индексы столбцов от 0 до 7.
    Когда сканируется правая половинка, прошивка должна знать, что её столбцы — это *продолжение* левых.
    Этот параметр сдвигает индексы правой части на 10. То есть, когда на правой половинке нажимается первый столбец (физически 0), прошивка считает его как столбец 10. Это позволяет иметь единую карту клавиш для обеих рук.

## /config/boards/shields/PNCATEHO/PNCATEHO.zmk.yml

Файл метаданных для ZMK Studio и GitHub Actions.

```yaml
id: PNCATEHO
type: shield
url: https://github.com/aroum/PNCATEHO
requires: [pro_micro]
features:
  - keys
```

Он описывает клавиатуру для инструментов: её ID, тип (shield, а не полноценная плата с впаянным контроллером), ссылку на репозиторий и требования (Pro Micro совместимый контроллер).
